원칙

  • 같은 개념이면 이름과 namespace가 같다. BCL·표준과 이름이 겹치면 C++ 쪽을 바꾼다.
  • 기능은 1:1로 맞추지 않는다. 같은 역할이면 충분하다. C#은 C++의 포팅이 아니라 C#다운 서버다.
  • 가져다 쓰는 것은 두 종류만: MS·표준 공식(BCL, C++ 표준)과 아주 대중적인 외부 라이브러리. 느리면 직접 만들고 벤치마크로 근거를 남긴다. 새 설치(vcpkg, NuGet)는 먼저 확인받는다.
  • 우선순위: 안전 > 성능 > 편의.

표시

구현 직접 만듦BCL·표준 공식 것을 그대로 씀 MS·대중 라이브러리 설치 필요 없음 그 언어엔 두지 않음
이름 확정 naming.md에 있음 제안 아직 정하지 않음 이름 겹침 BCL과 같은 이름이라 조정 필요

C++은 Core를 거의 다 만들어야 서버 코드를 쓸 수 있고, C#은 BCL 덕분에 Core가 얇다. 다만 성능이 갈리는 자리(직렬화, Lane, 패킷 자르기, 지연 측정)는 C#도 직접 만든다. 이 차이와 벤치마크 결과가 비교의 핵심이다.

정해야 할 것

  • 이름 겹침 Counter, DbConnection/DbCommand, namespace Timer(C# System.Threading.Timer와 겹침 → 예: Timing). 해당 단위 때 후보를 보여 드림.
  • Log C#: ILogger + 직접 만든 파일 출력 vs Serilog.
  • Config: C++ JSON 라이브러리 설치 여부.
  • CrashDump, Config를 Base에 넣을지.
