001 · Base 직렬화: ByteWriter / ByteReader

C++ · C# · 2026-11-23 · 커밋 4492703, 60e958d

무엇을 했나. 값을 바이트로 바꾸는 직렬화를 C#에 만들었다. C++에는 이미 있었다. 목표는 두 언어가 같은 값에서 같은 바이트를 만드는 것이다. 이 바이트가 패킷, 존 이동 데이터, DB 저장 데이터가 된다. C++은 템플릿과 if constexpr로, C#은 .NET에 이미 있는 IBufferWriter<byte>, MemoryMarshal, System.Text.Unicode.Utf8 위에 얇게 만들었다. C++을 C#으로 옮겨 적지 않았다.

이름. .NET에 System.IO.BinaryWriter가 있어서, C++의 BinaryWriter/BinaryReader/BinaryTraits를 ByteWriter/ByteReader/ByteTraits로 바꿨다. 이제 두 언어가 같은 이름이다.

클래스

C++Base::ByteWriter
  • vector<std::byte>를 소유한다. writer << a << b
  • operator<< 하나에서 if constexpr로 위에서부터 타입 판별(기본형 → 문자열 → optional … → 컨테이너), 마지막은 static_assert
  • 컨테이너, map, optional, variant, tuple, chrono, 고정 배열, SERIALIZE_FIELDS 클래스까지
C++Base::ByteReader
  • span<const std::byte>를 가리키기만 한다(복사 없음). 원본 수명은 주석 규칙으로 지킨다
  • 개수 > 남은 바이트면 실패(거짓 개수로 큰 메모리 잡기 방어), UTF-8 검사는 직접 만든 Base/Utf8.h
C#Base.ByteWriter (ref struct)
  • 버퍼를 갖지 않고 IBufferWriter<byte>에 쓴다. 테스트는 ArrayBufferWriter, 나중에 네트워크는 PipeWriter를 넘겨 소켓 버퍼에 바로 쓴다
  • 정수 전부는 Write<T>() where T : unmanaged, IBinaryInteger<T> 하나. 지원 안 하는 타입은 제약 조건에 걸려 컴파일 에러
  • string은 Encoding.UTF8.GetByteCount로 정확한 크기를 세고 Utf8.FromUtf16으로 바로 버퍼에 쓴다(중간 배열 없음)
C#Base.ByteReader (ref struct)
  • ReadOnlySpan<byte>를 가리키기만 한다. ref struct라 원본보다 오래 살거나 await를 넘기면 컴파일러가 막는다
  • UTF-8 검사는 .NET의 Utf8.IsValid
