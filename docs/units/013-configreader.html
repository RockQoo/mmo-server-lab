013 · ConfigReader: JSON 설정을 엄격하게 읽기

C++ · C# · 2026-11-28 · 커밋 8b8c40c ~ 18ef7c9

무엇을 했나. 서버가 시작할 때 JSON 설정 파일을 한 번 읽어 타입이 정해진 구조체(C#은 클래스)로 바꾸는 Base::ConfigReader를 만들었다. 포트, IOCP·Lane 수처럼 재빌드 없이 바꿀 값을 담을 틀이고, 처음 쓰는 곳은 다음 단위 Network와 ZoneServer main이다. 읽기만 한다(쓰기, 실행 중 다시 읽기 없음).

엄격하게 읽는다(안전 > 편의). 오타 키 하나, 범위 밖 숫자 하나가 조용히 무시되거나 잘려 들어가면 서버가 엉뚱한 값으로 뜬다. 두 언어 모두 같은 파일을 같은 규칙으로 읽고, 이상하면 위치를 적어 시작을 멈춘다.

정한 것

항목결정이유
형식JSON. 주석 허용, 끝 쉼표 금지데이터 형식은 JSON 하나로 통일(CLAUDE.md, journal/codegen.html). C++·C# 모두 라이브러리 기준을 넘는 형식이 JSON뿐이다. 끝 쉼표는 두 언어가 확실히 같게 읽도록 막는다
값 꺼내기타입 구조체(config.port)키 문자열(Get<int>("port"))은 오타가 실행해야 드러난다
실패로 보는 것빠진 키, 알 수 없는 키(오타), 담을 수 없는 값(70000 → uint16_t, -1 → 부호 없는 정수, 1.5·true → 정수, 1e100 → float), 타입 다름, 컬렉션 원소 null, 문법 오류시작할 때 한 번이라 엄격해도 비용이 없다. 틀린 설정으로 뜨는 것이 가장 비싸다
구조체는 누가쓰는 쪽(NetworkConfig는 Network, ZoneServerConfig는 ZoneServer)Core는 게임과 서버를 모른다. ConfigReader는 "JSON → 어떤 구조체든"만 한다
C++ 라이브러리nlohmann/json 3.12.0(vcpkg), 파싱만 맡긴다표준에 JSON 파서가 없다. 값 변환은 직접 검사한다(아래, 리뷰 R1~R3)
C# 라이브러리BCL System.Text.Json설치할 것이 없다. 옵션과 타입 정보 수정자로 같은 규칙이 된다
키 이름camelCase(C++ 필드 그대로, C#은 JsonNamingPolicy.CamelCase)두 서버가 같은 파일을 읽는다

바로잡음

  • C++ 첫 방식("읽은 뒤 다시 JSON으로 만들어 원본과 비교")은 틀렸다. 비교 하나로 알 수 없는 키와 잘린 값을 다 잡는다고 적었지만, nlohmann 은 부호가 섞인 정수를 int64로 바꿔 비교해 -1 과 UINT64_MAX를 같다고 보고(R1), 범위 밖 실수 → 정수는 비교 전에 이미 정의되지 않은 동작이며(R2), float 무한대는 양쪽이 같아 통과했다(R3). 넣기 전에 검사하는 방식으로 다시 썼다(117bc99). 덕분에 CONFIG_FIELDS에 타입 이름이 필요 없어졌다.
  • C#도 R3 과 같은 구멍이 있었다. C++ 리뷰에서 나온 입력(tickSeconds: 1e100)을 C# 테스트에도 넣자 실패해, System.Text.Json 이 float 1e100 과 double 1e400 을 오류 없이 ∞ 로 받는 것을 작은 프로그램으로 확인했다.

나중에

  • 같은 키가 두 번 나오면 두 언어 모두 마지막 값으로 덮는다(같은 동작이라 지금은 둠). 막을지는 설정 파일이 커질 때 본다.
  • enum 필드("logLevel": "Info")는 쓰는 곳이 생기면 이름으로 읽는다(C++ magic_enum).
  • 시간 길이 필드(std::chrono / TimeSpan)도 쓰는 곳이 생길 때.
