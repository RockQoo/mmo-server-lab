003 · C# Assert, 경고를 가장 높게 + 경고 = 빌드 에러

C++ · C# · 2026-11-24 · 커밋 9790c5d, 8cb71e6

무엇을 했나. (1) C#의 검사(Assert)는 새로 만들지 않고 BCL(Base Class Library: .NET 기본 제공)의 Trace.Assert / Debug.Assert를 쓰기로 했다. 직접 돌려 보니 C++ ASSERT / DEBUG_ASSERT와 역할이 같았다. (2) 두 서버 모두 경고를 가장 높은 단계로 켜고, 경고가 하나라도 나오면 빌드가 실패하게 했다. 끄는 것은 해당 없는 규칙만, 가장 좁은 범위로, 이유를 적어서 끈다.

Assert: 같은 역할, 다른 방법

역할C++ (직접 만듦)C# (BCL)
항상 검사(Release 포함)ASSERT(조건, 메시지)Trace.Assert(조건, 메시지)
Debug에서만(비싼 검사)DEBUG_ASSERTDebug.Assert
실패하면 기록stderr + VS 출력 창(조건식 글자 포함)stderr(메시지 + 파일·줄이 담긴 호출 스택)
디버거가 붙어 있으면__debugbreak그 자리에서 멈춤
잡아서 무시하지 못하게 종료RaiseException(0xE000A55E) → abortEnvironment.FailFast(종료 코드 0x80131623), try/catch 불가
덤프나중에 CrashDump(SetUnhandledExceptionFilter)런타임 설정(DOTNET_DbgEnableMiniDump=1)
검사가 빌드에서 사라지지 않게매크로라 항상 남음Trace.Assert는 TRACE 기호가 있어야 남는다 → Directory.Build.props에 명시, 빠지면 AssertTest가 깨짐

받은 데이터 검사(패킷 길이 등)에는 Assert를 쓰지 않는다. 그건 실패 표시(IsValid)로 처리한다. Assert는 "코드가 틀렸다"는 뜻이다.

경고 정책

C++ (MSVC)
  • /Wall: 가장 높은 경고 단계
  • /analyze: 정적 분석(널 역참조, 버퍼 넘침, 초기화 안 된 값)
  • 컴파일·링크 /WX: 경고 = 에러
  • /external:anglebrackets /external:W0: 표준·vcpkg 헤더는 보지 않는다(우리 코드가 만든 템플릿 인스턴스는 본다)
  • 끈 것: 안내성 C4514·C4710·C4711(inline 안내), C4820(패딩 안내), C5045(Spectre 안내). 테스트만 C6326(gtest 매크로 오탐)
C# (.NET)
  • WarningLevel 9999: 컴파일러 경고 새 단계(warning wave)까지 전부
  • AnalysisLevel latest-all: 코드 분석(CA) 규칙 전부
  • Features strict: 컴파일러 엄격 모드
  • TreatWarningsAsErrors: 경고 = 에러
  • 끈 것: 코덱 파일에서만 CA1815(struct 비교 재정의: 비교하지 않는 표시용 타입), CA1000(제네릭 static 멤버: static abstract 구현) — .editorconfig
