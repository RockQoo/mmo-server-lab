004 · Messaging: Lane, 코딩 규칙 검사

C++ · C# · 2026-11-24 · 커밋 23ef9bd, f44fa65, 52e385f, 3363d49, 60b1831

무엇을 했나. 새 라이브러리 Messaging을 만들고, 첫 클래스 Lane을 C++과 C#으로 만들었다. Lane은 일(함수)을 받아 넣은 순서대로, 한 번에 하나씩 처리한다. 존 하나처럼 한 Lane에 묶인 데이터는 그 Lane의 일만 만지므로 락 없이 쓸 수 있다(스레드 어피니티). 여러 Lane 중 키(존 ID 등)로 하나를 고르는 묶음은 다음 단위에서 만든다.

왜 Base가 아니라 Messaging인가

  • 경계는 "스레드를 만들고 돌리는가"다. Base(직렬화, Assert, UTF-8, 이후 RwLocked<T>)는 스레드를 갖지 않는 부품이고, Messaging은 스레드를 소유하고 일을 처리한다.
  • 의존 방향이 한쪽으로만 흐른다: Base ← Messaging ← Log·Network ← 서버. 비동기 로거도 이 큐를 쓴다.
  • 스레드 테스트는 느리고 타이밍에 민감하다. MessagingTests로 나눠 Base 테스트는 빠르고 결정적으로 둔다.

흐름 (C++)

Lane 스레드는 일이 들어오거나 멈춤 요청이 올 때까지 condition_variable_any에서 잔다. 멈춤 요청이 와도 남은 일이 있으면 먼저 처리하고, 비었을 때 끝난다.

클래스: Lane

C++
  • Post: 같은 락 안에서 "멈춤 요청 확인 + 넣기". Run이 "비었고 멈춤 요청됨"을 보고 끝난 뒤에는 반드시 멈춤이 보이므로, 끝난 Lane에 넣고 잃어버리는 일이 없다
  • 비어 있지 않았으면 깨우지 않는다(이미 깨어 있거나 깨우는 중)
  • 스레드는 생성자 본문에서 시작한다(초기화 목록에서 this를 넘기면 C4355)
  • 복사·이동 금지(스레드가 this를 쥐고 있다)
C#
  • sealed class + IAsyncDisposable
  • 멈춘 뒤 TryPost는 Channel이 닫혀 false
  • 라이브러리 코드라 await마다 ConfigureAwait(false)(CA2007을 지킴)
  • 테스트에서만 CA2007을 껐다: xUnit은 테스트 안에서 ConfigureAwait(false)를 쓰지 말라고 한다(xUnit1030)

코딩 규칙: 왜 어긋났고, 어떻게 막나

무슨 일이 있었나. Lane C++ 멤버를 mutex_처럼 뒤에 _를 붙여 썼다. 규칙(docs/coding-style.md)은 앞에 붙이는 _camel이고 Base는 그렇게 되어 있었다. 멤버 {} 초기화와 지역 변수 auto도 빠졌다. 규칙 문서를 다시 보지 않고 썼고, 그것을 잡아 줄 검사가 없었다. 그래서 규칙은 사람이 기억하지 않고 도구가 검사한다로 바꿨다.

변수 이름: 두 언어가 같은 규칙

범위C++C#왜 나누나(스레드)
멤버(private·protected)_pending_pending객체 하나에 속한다
statics_counts_count모든 스레드가 같이 본다

지역·매개변수 / 상수running / MaxCount같음

C# 은 MS 공식 규칙(_camel, s_, t_)이다. C++ 에서는 m_가 더 흔하지만 두 서버가 같은 모양이도록 C# 쪽에 맞췄다. 멤버에 쓰는 _+소문자는 C++ 표준상 문제없다(예약은 _+대문자, __, 전역 범위의 _).

검사 도구

C++
  • .clang-format: 서식(있었지만 적용·검사를 안 했다. Base 파일 3개도 어긋나 있었다)
  • .clang-tidy: 이름 규칙(readability-identifier-naming) + 버그가 되기 쉬운 코드(bugprone-*)
  • server-cpp/lint.ps1: 둘 다 돌림, -Fix로 고침. MSVC 빌드 명령에서 clang이 모르는 /analyze, /Wall은 뺀다(RemovedArgs)
  • 끈 것: easily-swappable-parameters(모든 함수가 걸려 신호 없음), main의 예외 검사(빠져나가면 크래시 → 덤프가 우리 정책)
C#
  • .editorconfig 이름 규칙(IDE1006)·서식(IDE0055) + EnforceCodeStyleInBuild → 빌드 에러
  • build.ps1 -Lint: dotnet format --verify-no-changes
  • 한계: editorconfig는 [ThreadStatic]을 구분하지 못해 t_도 s_로 요구한다. t_currentLane 한 곳만 그 자리에서 끄고 이유를 적었다
  • 일부러 틀린 임시 파일로 멤버·static·매개변수 위반이 모두 걸리는 것을 확인했다

qa.json이 두 언어 lint를 함께 돌린다(빌드·테스트 → lint).
