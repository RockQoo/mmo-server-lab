002 · C# 직렬화: 코덱으로 컨테이너·nullable·Dictionary·클래스

C# (C++ 따라잡기) · 2026-11-24 · 커밋 43ae8cc ~ 9c5d808

무엇을 했나. C++ ByteWriter/ByteReader가 이미 지원하던 컨테이너, optional, map, 클래스를 C#에서 같은 바이트로 쓰고 읽게 했다. 정답 파일 두 개(containers.hex, classes.hex)를 두 언어 테스트가 같이 확인한다.

왜 이 방식인가. C++은 operator<< 하나 안의 if constexpr로 타입을 컴파일 시간에 가른다. C#에는 그 기능이 없다. 그래서 타입마다 쓰기·읽기 묶음인 코덱(codec: 인코더 + 디코더)을 struct로 두고 static abstract 인터페이스(IByteCodec<T>)로 묶었다. JIT(Just-In-Time 컴파일러: 실행할 때 기계어로 바꾸는 .NET 컴파일러)가 struct 코덱마다 전용 코드를 만들어 호출이 인라인된다. 규칙 "안전 > 성능 > 편의"에 따라 편의(짧은 코드)보다 성능을 골랐다. 손으로 쓰면 길지만 패킷·데이터 클래스는 CodeGen이 만든다.

안전 (C++과 같은 규칙)

  • 거짓 개수: 개수 × 원소 크기가 남은 바이트보다 크면 할당 전에 실패(ReadCount(minElementSize)). long 65535개짜리 512KB 배열을 데이터 없이 만들게 하지 못한다.
  • 실패한 nullable: "있음" 뒤 값 읽기에 실패하면 0이나 ""가 아니라 null(C++ optional을 비우는 것과 같다).
  • null 쓰기: null 문자열·배열·List·Dictionary·클래스는 예외 대신 실패 표시(ByteWriter.Fail()), 이후 쓰기 무시.
  • 실패 뒤: 컨테이너 읽기가 실패하면 빈 컨테이너. 끝에서 IsValid로 한 번 확인한다.
